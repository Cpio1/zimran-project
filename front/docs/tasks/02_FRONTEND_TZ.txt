ТЗ ДЛЯ CLAUDE CODE — FRONTEND

Требование организаторов: MVP открывается сразу без регистрации, логина, пароля, обязательного email и экрана авторизации. Backend незаметно создаёт анонимную демо-сессию. Это требование имеет приоритет над прежними заданиями.
Рабочая папка: apps/frontend
Ветка: work/front
Сервис: Next.js + TypeScript + Tailwind, порт 3000.
Ты отвечаешь только за Frontend. Создай рабочий интерфейс и адаптер к точному API, не ограничивайся дизайном.

Общий контекст для всех трёх частей
Claimly — B2C веб-приложение для пользователей США 25–45 лет. Оно хранит гарантии, страховки, сервисные договоры, сертификаты, условия членств, чеки и возвраты; находит оплаченные или бесплатные преимущества; напоминает об использовании; отвечает по документам; помогает с обращениями и результатами.
Четыре модуля MVP: Vault; Benefits и Reminders; Assistant и Benefit-to-Need Matching; Claims и Case Tracking.
Полный объём: 99_Product_MVP_Source.txt. Архитектура и обязательные правила: 00_START_HERE.txt. Машинные контракты: contracts/backend.openapi.json и contracts/llm.openapi.json, версия 2.0.0. Примеры: fixtures/*.json.

Правила совместимости
- Сначала прочитай общий контекст, контракты и примеры. Не переименовывай поля, статусы, маршруты или enum под свой вкус.
- Изменение contracts/* согласуется с интегратором и применяется у всех. Обычные внутренние реализации выбирай самостоятельно.
- Успех HTTP: {data, request_id}; список: {data: [], next_cursor, request_id}; ошибка: {error: {code, message, retryable}, request_id}. 204 не содержит тела.
- Неизвестные значения — null. ID — UUID. Даты — YYYY-MM-DD, техническое время — ISO 8601 UTC. Деньги — целые центы; валюта USD.
- Следуй назначению required и nullable в OpenAPI. Списки со страничной выдачей сортируются стабильно.
- У дорогих и повторяемых операций используй Idempotency-Key; повтор с тем же ключом возвращает тот же результат, другой payload с этим ключом — 409.
- Во всех ответах добавляй X-Contract-Version: 2.0.0. /health возвращает статус сервиса и contract_version.
- Нельзя выдавать sample-ответ за настоящий анализ. У функций без ключей — честное состояние и инструкция настройки.


1. ГРАНИЦА ОТВЕТСТВЕННОСТИ

Твоя часть: страницы, формы, навигация, адаптивность, автоматическое создание и восстановление демо-сессии, API-клиент, ожидание jobs, отображение источников, клиентские проверки и состояния интерфейса.

Не создавай бизнес-API в Next.js, свою БД, очередь, OCR или вызовы модели. Не обращайся к таблицам/Storage Supabase напрямую. Не храни секреты LLM или service_role.

Все данные приходят через Backend. Браузер вообще не подключается к Supabase. Не устанавливай Supabase Auth SDK и не создавай Login/Register/Logout, OAuth, auth middleware или обязательный ввод email.

2. СОВМЕСТИМОСТЬ

Используй contracts/backend.openapi.json как источник TS-типов и клиента. Можно сгенерировать типы доступным инструментом или реализовать их строго по схемам. Не сокращай API-форматы ради удобства компонента.

Один API client:
- base URL из NEXT_PUBLIC_API_BASE_URL без /api/v1 в конце.
- Добавляет /api/v1/... по контракту.
- Перед первым запросом данных читает demo session_token из localStorage.
- Если токена нет, сам вызывает POST /api/v1/demo/sessions без тела и учётных данных.
- Сохраняет session_token и expires_at; все запросы данных отправляет с X-Demo-Session.
- Создание сессии запускается через один общий promise, чтобы параллельные компоненты не создавали разные пространства.
- /health и создание демо-сессии доступны без токена.
- При 401 DEMO_SESSION_REQUIRED/DEMO_SESSION_EXPIRED очищает старую сессию и автоматически создаёт новую один раз. Сообщи, что прежняя демо-сессия закончилась; не предлагай логин.
- После смены сессии инвалидируй кэш. Не повторяй автоматически прежние мутации, связанные со старыми UUID; GET можно перезапросить.
- Для multipart не задаёт Content-Type вручную: boundary формирует браузер.
- Для повторяемых POST/PUT создаёт и сохраняет Idempotency-Key до завершения операции; retry использует прежний ключ.

PATCH с expected_version получает актуальную версию сущности. На 409 показывай конфликт и предложи обновить данные, а не затирай их.

3. ЭКРАНЫ

Открытие приложения:
Сразу показывай Home. Короткий начальный loader разрешён только на время автоматического создания демо-сессии; отдельного auth-экрана нет. Не требуй аккаунт, пароль, email, телефон или имя. После refresh используй сохранённый токен и прежние документы/чат. Можно добавить необязательную кнопку Start new demo с подтверждением; она очищает локальный токен и создаёт новое пространство, не затрагивая другие сессии.

Home:
Главное действие Upload document; Next actions; несколько актуальных преимуществ; ближайшие напоминания; активные дела; раздельные показатели денег и услуг. Не показывай номинал сертификата как наличные.

Vault:
Список с фильтром категорий и поиском; страница записи с документами, фактами, преимуществами, сроками и связанными делами. Поддержи standalone страховку/сертификат без обязательной покупки.

Upload:
Создай Entry через Backend, затем загрузи file + entry_id. Для пяти файлов — отдельные запросы в ту же запись. При неуспешной загрузке сохрани понятный черновик записи и возможность продолжить.

Poll Job и покажи состояние. После окончания запроси свежие Document, Entry и Benefits; не подставляй LLM JSON напрямую в собственную локальную БД.

Review:
Покажи важные факты, дату, лимиты, источники, Needs review. Ручные правки отправляй в Backend. Изменения исходного документа и устаревший анализ видимы.

Benefits:
Карточки услуги, покрытия, сертификата и членства; условия и цитаты в деталях. usage_state=unknown означает, что использование надо уточнить, а не ноль.

Действия:
- Ask Claimly открывает thread выбранной записи.
- Plan to use создаёт дело benefit_use, но не списывает единицы.
- Mark used запрашивает подтверждённое суммарное использованное количество и отправляет PUT usage.
- Покажи результат total=4, used=1, remaining=3. При неизвестном total не выдумывай остаток.

Assistant:
Полноценный чат с историей из Backend. Поддержи общий thread, thread записи и отдельный thread дела. Вопрос о потребности использует purpose=match_need; обычный — answer.

Показывай ответ, цитаты, подходящие benefits, вопросы и допустимые next_actions. Действия из модели сопоставляй с разрешёнными типами и известными ID; не исполняй произвольные URL.

Cases:
Список, детали, оценка, постоянный чат, события, документы, редактируемый Draft, ответ компании, follow-up, результат. Copy не отмечает отправку.

Разбор ответа компании:
Можно вставить текст либо выбрать загруженный документ и отправить ReplyCreate. Покажи job и затем событие с ReplyAnalysis.

Calendar/Notifications:
Agenda на неделю/месяц, переходы к преимуществу/делу, редактирование времени и интервалов 30/14/7/1/0. Часовой пояс IANA. Email не обещай, если profile.email_configured=false. notification_email вводится только добровольно в настройках уведомлений; согласие явно изменяет профиль. Для основного сценария поле не требуется.

4. JOBS И СОСТОЯНИЯ

Для 202 забирай job.id. Опрашивай GET /api/v1/jobs/{id} с умеренным интервалом и backoff. Останавливай polling на terminal status или размонтировании, поддерживай возвращение на страницу.

queued/running — обработка; succeeded — обновление данных; failed — ошибка и допустимый retry; stale — сведения изменились, нужен новый анализ; cancelled — задача отменена.

progress=null отображай как неопределённый индикатор. Не рисуй выдуманные проценты.

В пользовательском сообщении чата отображай сохранённый message сразу, затем ожидай assistant_message из результата job. Не добавляй второй экземпляр одного сообщения при повторе poll.

5. ИСТОЧНИКИ И ФАЙЛЫ

EvidenceRef открывает документ через Backend /content с X-Demo-Session. Для PDF покажи соответствующую страницу и цитату; для фотографии — изображение и текст.

Покажи предупреждение, если document_version источника устарел. Удалённый или недоступный источник не заменяй фиктивным preview.

Не передавай demo session_token в query string. Получай байты запросом с X-Demo-Session, используй object URL, освобождай его при закрытии.

6. MOCK-РЕЖИМ ДЛЯ РАБОТЫ БЕЗ BACKEND

Один и тот же API-адаптер переключается через NEXT_PUBLIC_API_MODE=mock|http.
В mock используй MSW или эквивалентный перехватчик запросов с точно теми же маршрутами, envelope, ошибками и fixtures.

Mock должен поддерживать состояния, а не только постоянные ответы: начало/окончание Job, изменение usage, редактирование черновика и переход между страницами. Он может хранить демо-данные локально, но помечается Sample mode и повторяет автоматическое создание демо-сессии в http-режиме.

Для перехода к реальному Backend достаточно изменить mode и base URL. Компоненты страниц переписывать не должно требоваться.

7. ВНЕШНИЙ ВИД

Современный спокойный интерфейс, единая типографика, светлая база, короткие подписи и одно главное действие в контексте. На desktop боковая навигация; на mobile компактная навигация и удобные карточки.

Не показывай сразу все поля и технические состояния модели. Источники и длинные условия — по запросу. Чат доступен рядом с контекстом.

Проверь 375, 768, 1440 px, клавиатурную навигацию, отсутствие горизонтального скролла и перекрытия кнопок.

8. ПЕРЕМЕННЫЕ И ЗАПУСК

NEXT_PUBLIC_API_BASE_URL=http://localhost:8000
NEXT_PUBLIC_API_MODE=mock

В http-режиме нужен только адрес Backend. Frontend не нужны Supabase credentials. Service role, scheduler secret и LLM token сюда не добавляй.

Зависимости и lockfile — только apps/frontend. Предоставь команды dev/build/typecheck/test и Dockerfile. Учитывай, что NEXT_PUBLIC переменные задаются при сборке.

9. ПРИЁМКА И ПЕРЕДАЧА

Проверь flows: открытие ссылки без логина → автоматическая демо-сессия → refresh с сохранением данных; загрузка → job → review → benefit; сертификат 4/1/3; вопрос в чате; matching; дело → draft → Copy → отметка отправки; ответ компании; follow-up; календарь; unknown/null; ошибки 401/409/503; mobile.

Обязательны сборка, типы и осмысленная проверка адаптера и ключевых пользовательских действий.
Передай UI, API client, mocks, .env.example, Dockerfile, README и результаты проверок.
Не редактируй services/backend, services/llm и contracts без согласования.
